# CNAPS 付款/收款地址及付款人开户行字段设计

## 目标

在现有无账号系统、无业务请求头的单表 CRUD POC 中，为单据增加三个可选业务字段，并保持 Mock 与真实 Tuxedo/Oracle 链路一致：

- `payerAddress`：付款人地址，最长 256 个字符；
- `payeeAddress`：收款人地址，最长 256 个字符；
- `payerBankName`：付款人开户行，最长 128 个字符。

录入接口可以保存这些字段，修改接口可以编辑或清空这些字段，详情接口返回这些字段。列表和待复核列表不增加这些字段。

## 范围与非目标

本次修改只扩展现有单据字段链路，不增加账号、登录、权限、身份校验、业务请求头或额外状态逻辑。

涉及范围：

- HTTP JSON 请求和详情响应映射；
- Mock 内存数据链路；
- FML32 字段定义与 Jolt 服务元数据；
- Tuxedo 原生录入、修改、详情服务；
- OCI 行结构、插入、更新和详情查询；
- Oracle 新建表 DDL 与现有数据库增量迁移；
- API/数据库文档和自动化测试。

明确不涉及：

- 通用列表和待复核列表的响应字段扩展；
- 新的查询条件；
- 新错误码；
- 新的账号、认证或授权逻辑。

## HTTP 接口契约

### 录入接口

`POST /api/cnaps/vouchers` 接受三个可选字符串字段：

```json
{
  "payerAddress": "上海市浦东新区示例路 1 号",
  "payeeAddress": "北京市朝阳区示例路 2 号",
  "payerBankName": "中国示例银行上海分行"
}
```

字段未传或传入空字符串时允许保存为空。原有必填字段、默认值和状态规则保持不变。

### 修改接口

`PUT /api/cnaps/vouchers/{billId}` 接受相同的三个可选字段，采用 PATCH 式字段语义：

- 字段未传：保留数据库中的原值；
- 传入非空字符串：覆盖为新值；
- 传入空字符串 `""`：将该字段清空。

原有可修改状态、版本号和状态回置规则保持不变。

### 详情接口

`GET /api/cnaps/vouchers/{billId}` 的 `data` 增加：

```json
{
  "payerAddress": "上海市浦东新区示例路 1 号",
  "payeeAddress": "北京市朝阳区示例路 2 号",
  "payerBankName": "中国示例银行上海分行"
}
```

空值沿用当前详情链路的空值表达方式。通用列表和待复核列表不输出这三个字段。

## 数据流设计

WebFE 请求映射将三个 JSON 字段转换为内部 FML32 字段：

- `payerAddress` → `PAYER_ADDRESS`；
- `payeeAddress` → `PAYEE_ADDRESS`；
- `payerBankName` → `PAYER_BANK_NAME`。

录入服务读取三个字段并绑定到 Oracle `INSERT`。修改服务只覆盖请求中实际出现的字段，并允许用空字符串清空。详情服务从 Oracle 行结构读取并输出三个字段。

详情输出使用详情服务专属字段写入，避免共享的分页行输出自动把新字段扩展到列表接口。Jolt 仅为录入、修改输入和详情输出登记相应字段。

Mock 模式执行相同的录入、修改和详情语义；分页结果在输出前排除三个字段，保证两条链路对外契约一致。

## 数据库设计与迁移

`CNAPS_BILL_POC` 增加三个可空列：

```sql
PAYER_ADDRESS   VARCHAR2(256 CHAR),
PAYEE_ADDRESS   VARCHAR2(256 CHAR),
PAYER_BANK_NAME VARCHAR2(128 CHAR)
```

全新建库 DDL 直接包含这些列。另提供可重复执行的增量 SQL：执行时检查列是否存在，仅对缺失列执行 `ALTER TABLE ... ADD`。这样现有虚拟机数据库可原地升级，不需要删表、重建或清理已有 POC 数据。

部署时必须先完成数据库增量迁移，再启动引用新列的原生服务版本。

## 校验与错误处理

录入和修改接口统一校验字符长度：

- `payerAddress`、`payeeAddress` 不超过 256 个字符；
- `payerBankName` 不超过 128 个字符。

超长输入沿用现有参数格式错误响应，不新增错误码。数据库或 OCI 异常继续沿用现有数据库错误响应。三个字段均不做字典校验，也不引入地址或银行名称真实性校验。

## 测试与验收

自动化测试覆盖：

- 录入携带三个字段后，详情原样返回；
- 修改传入新值时正确覆盖；
- 修改未传字段时保留原值；
- 修改传入空字符串时清空字段；
- 录入和修改拒绝超过最大长度的字段；
- 通用列表和待复核列表不出现三个新字段；
- Mock 请求/响应、Jolt 元数据、FML32 定义和 C/OCI 源码契约保持一致；
- 增量 SQL 可重复执行且不会删除现有数据；
- Maven 测试和原生 C 构建检查通过。

验收以无业务请求头的 HTTP CRUD 调用为准，不增加账号或认证前置条件。

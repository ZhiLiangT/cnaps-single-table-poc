## 1. 测试目标与边界

验证 CNAPS 凭证单级审核闭环满足以下结果：

```text
创建 -> 待审核 -> 审核通过
创建 -> 待审核 -> 审核退回 -> 修改 -> 再次待审核
```

本手动测试用例集覆盖：

- 待审核列表的路由、筛选、分页、机构隔离和响应契约。
- 审核通过、审核退回的状态、审计、版本和响应字段。
- 重复审核、非法状态、凭证不存在、并发竞争和事务回滚。
- HTTP、Tuxedo 和数据库错误的业务码映射。
- 服务声明、Jolt 元数据和“不新增 `CNAPS5702Q`”等结构约束。

本测试不覆盖登录、权限、录入审核分离、审核意见、退回原因、批量审核、多级审核、通知、外部工作流或真实 CNAPS 外发。

## 3. 测试环境与数据

### 3.1 环境前提

- 使用真实 WebFE、Jolt、Tuxedo 和 Oracle 集成环境，避免 Mock 行为被误当成验收结果。
- WebFE 固定上下文记为：`operatorNo=OP_REVIEW_01`、`branchNo=772`；每次请求生成唯一 `requestId`。
- 数据库和应用服务器时钟已同步；记录测试开始时间 `T0` 和结束时间 `T1`。
- 并发用例使用屏障同时释放两个独立连接，不把串行快速调用当作并发。
- 故障用例只在可恢复的隔离环境执行，并在用例后恢复数据库和 Tuxedo 服务。

### 3.3 通用断言

除用例另有说明外，每个返回 JSON 的 HTTP 业务响应均检查：

1. HTTP 状态与业务码一致。
2. 顶层字段恰好为 `respCode`、`respMsg`、`data`。
3. 成功时 `respCode=0000`；失败时 `data=null`。
4. 写操作前后查询数据库，验证目标字段和明确要求“不变”的字段。
5. 时间字段不为空、可按 `yyyy-MM-dd HH:mm:ss` 解析，并处于 `[T0, T1]`；不对 Oracle 时间做毫秒级相等断言。

GET 审核路径的 HTTP 405 按设计直接返回空响应，不套用 JSON 信封通用断言。

## 7. 执行顺序与退出准则

建议按以下顺序执行，以降低环境故障对结果的干扰：

1. `STR-*` 静态结构检查。
2. `API-*` 与 `LST-*` 只读/低破坏性用例。
3. `ACT-*` 状态流转与审计用例。
4. `CON-*` 并发用例。
5. `TXN-*`、`ERR-*` 故障注入用例。

发布验收必须满足：

- 所有 P0、P1 可执行用例通过，P2 无阻断性失败。
- 不存在未解释的 HTTP 状态、业务码、数据库状态或版本差异。
- 并发用例至少连续执行 20 轮，每轮均恰好一个成功且版本只加 1。
- 所有失败写操作均证明无部分提交。
- `REV-TBD-001`、`REV-TBD-002`、`REV-TBD-004` 在正式发布前完成契约确认并补充手动步骤；`REV-TBD-003` 完成环境方案确认。
- 测试报告包含环境版本、数据 ID、请求/响应、数据库前后快照、并发双方结果和缺陷链接。
